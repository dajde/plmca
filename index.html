Pattern Logic for Model Checking Automata

This tool can be used to declaratively verify structural properties of finite automata.

On the left side you can input a finite automaton in a text format as a list of transitions. On the right side you can input the pattern logic formula. You can run the model-checker by clicking the 'Run' button.

The finite automata transitions are in the format "state1 -> state2 : letter". An underscore ("_") in the beginning of the name of the state marks an initial state, a star ("*") at the end of the name of the state marks a final state.

The formula is in the format "exists path : state1 -- word -> state2, ..., boolean_formula", where the part beginning with "exists..." is a path declaration with the name of the path variable "path", name of the starting state variable "state1", name of the input word variable "word" and name of the ending state variable "state2". "boolean_formula" is a boolean combination (and (/\), or (\/), negation (!)) of atomic predicates over the variables. Note that that "state1" and "state2" do NOT have to be initial or final states, respectively. There can be an arbitrary number of path declarations.

The available predicates are:
- x = y (state, input word or path x is equal to y)
- x <= y (input word length of x is less than or equal to y)
- x $> L (input word x belongs to language L)
- x #> y (input word x is a prefix of y)
- init x (initial state)
- final x (final state)
- reach_init x (state is reachable from initial state)
- reach_final x (final state is reachable from state)

To use the language inclusion predicate, you need to define the languages via the "Add Language Automaton" button.

It is also possible to use universally quantified formulas, where the quantification is over states. Then the formula begins with "forall p ...", where "p" is a state variable appearing in some path declaration.

The program also supports finite automata with outputs. The format of the transition is then "state1 -> state2 : letter, output", where "output" can be either 1. a number or 2. a sequence of letters separated by "|". If all of the transitions fulfill 1., the program considers it a sum automaton, if all transitions fulfill 2., the program considers it a transducer. In this case the formula path declarations have the format "exists path : state1 -- word, output -> state2", where "output" is an output variable. For sum automata, the program supports the output disequality of terms built from "+" (summation) of output variables. For transducers, the program supports the output language inclusion of terms built from "." (concatenation) of output variables.

There are example automata and formulas to illustrate the usage.
